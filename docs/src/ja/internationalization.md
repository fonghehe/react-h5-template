# アプリの国際化とドキュメント言語

**アプリ**は `en-US`、`zh-CN`、`ja-JP`、`zh-HK`、`zh-TW` の 5 言語、**ドキュメント**は英語 `/`、簡体字中国語 `/zh/`、日本語 `/ja/` です。5 言語 UI が DB の全商品フィールドや docs の 5 翻訳を意味するわけではありません。

言語は Zustand の永続セッション設定です。`AppProviders` がクライアントで復元して `<html lang>` を設定し、会員画面の picker で変更します。`useTranslation()` はラベル、検証表示、アクセシビリティ文言と RMB 表示を担当し、対応アダプターにも言語を渡します。商品 Query Key に locale が入るので英語のキャッシュを日本語に使いません。API は `Accept-Language` を送り、サーバーは重みを解釈してメッセージとデモ商品を選びます。

`packages/i18n/src/messages.ts` は同一キーの 5 つの辞書を定義し、TypeScript がキー不足を検出します。Zod の中国語内部エラーテキストをそのまま表示せず、画面で翻訳ラベルへ対応させます。サーバーエラーの辞書は `packages/server/src/http.ts` にあります。翻訳文章を安定したエラー識別子にしないでください。

同梱商品は言語別の表現を持ちますが、PostgreSQL Repository は中英日 3 つの商品名列だけを切り替え、店舗、配送、説明は共通列です。香港/台湾は中国語名を使います。本番の商品システムには編集可能な翻訳モデル、欠落時 fallback と校閲が必要です。通貨は言語ごとの RMB 表示であり、レート換算や多通貨決済ではありません。

全 sidebar テーマに英中日の同名ページがあります。`docs/.vitepress/config.mts` が言語メニュー、ナビ、Pages の base path を定義します。契約や機能を変える際は英語を先に直し、`/zh/` と `/ja/` でコマンド・endpoint・現在/提案の意味をそろえ、`pnpm build:docs` で 3 系統を検証します。
