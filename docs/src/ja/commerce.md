# 商品からチェックアウトまで

現状は商品閲覧からローカルのチェックアウト模擬まで動きますが、注文・決済システムではありません。

1. `/products` は `/api/products` を呼び、サーバーがページ番号と件数を検証して PostgreSQL または同梱データを読みます。読み込み、エラー/再試行、引っ張って更新、追加読み込みがあります。
2. `/products/[id]` は商品詳細を取得し、商品スナップショットをローカルカートへ追加します。お気に入りボタンはページ内だけの状態です。
3. `/cart` は Zustand の商品・数量・選択状態を表示し、増減、全選択、削除とスナップショット価格の合計を計算します。
4. `/checkout` は React Hook Form と Zod で受取人、中国大陸形式の携帯番号、住所、単一のデモ決済値を検証します。確認後、選択行をローカルカートから削除して商品画面へ戻します。

チェックアウトは **HTTP 注文リクエストを送らず**、注文行も保存せず、課金もしません。詳細画面の会員価格は表示のみで、カートは通常の `price` を使います。「支払う」という UI 文言はデモであり、決済連携の証拠ではありません。

ブラウザー内の商品と価格は編集可能で、古くなることもあります。DB には現状 `products` と `users` だけがあり、注文、在庫、支払試行、配送先テーブルはありません。本番の注文 API は商品 ID、数量、配送情報、冪等キーを受け、1 つのトランザクションで最新価格を読み、在庫を予約し、注文と確定価格の明細を保存します。サーバーが注文 ID と計算済み合計を返した後でのみ、クライアントは提出済みカート行を消します。

支払いは別の状態機械です。検証済み事業者 Webhook が届くまでは `pending_payment`、成功時だけ `paid` とし、失敗・期限切れでは在庫を解放します。二重送信と重複 Webhook は安全に再処理できる必要があります。金額は最小通貨単位の整数か精密 Decimal を使用し、UI の浮動小数表示を注文金額に使いません。[改善計画](/ja/roadmap)に実装順序があります。
