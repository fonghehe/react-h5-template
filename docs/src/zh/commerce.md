# 商品、购物车与结算边界

当前流程可从浏览商品走到本地结算，但它是教学演示，不是订单或支付系统。

1. `/products` 请求 `/api/products`，服务端校验页码和每页数量，再从 PostgreSQL 或内置数据读商品。页面有加载、错误/重试、下拉刷新和滚动加载。
2. `/products/[id]` 读单个商品，并把其商品快照加入本地购物车。收藏按钮只改页面状态。
3. `/cart` 的 Zustand 行记录商品、数量与选择状态；页面可加减、全选、移除，并用快照价格算总额。
4. `/checkout` 用 React Hook Form 与 Zod 校验收货人、中国大陆格式手机号、地址和唯一的演示支付值。确认弹窗之后只删除选中的本地购物车行并跳回商品页。

结算**没有发送 HTTP 订单请求**，没有订单表、库存预留或真实扣款。详情页展示会员价，但当前购物车按 `price` 计算。界面中的“支付”按钮是演示文案，不能用来说明已经接入支付。

浏览器存储可以被修改，也可能保存过时价格，因此客户端总额不能作为权威订单金额。现有数据库只有 `products` 和 `users`，没有 `orders`、`order_items`、库存台账、支付尝试或地址表。真实订单 API 应只接收商品 ID、数量、配送信息及幂等键，在同一数据库事务中读最新价格、预留库存、写订单和固定价格的订单行，再返回服务端计算的总额与订单 ID。只有服务器确认成功后客户端才清掉提交的购物车行。

支付应单独建状态机：待支付、已支付、失败、过期；经过验证的服务商 Webhook 才能把订单改为已支付，失败或过期时释放库存。重复提交与重复 Webhook 要可安全重放。金额使用最小货币单位整数或精确 Decimal；现有演示价格是按人民币元展示的整数，不应让浮点格式化值进入真实结算。[改进路线](/zh/roadmap)按顺序列出实现步骤。
