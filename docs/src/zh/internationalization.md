# 应用国际化与文档语言

**应用**支持 `en-US`、`zh-CN`、`ja-JP`、`zh-HK`、`zh-TW` 五种语言。**文档**以英文 `/` 为默认，简体中文在 `/zh/`，日文在 `/ja/`。五语言 UI 不表示数据库所有内容或文档也有五份翻译。

语言偏好存于持久化的 Zustand 会话。`AppProviders` 在客户端恢复状态并设置 `<html lang>`；个人中心 Picker 更新偏好，`useTranslation()` 负责页面文案、校验提示、无障碍标签和人民币格式。适配器在其支持范围内接收同一语言。商品 Query Key 包含 locale，切换语言不会把英文缓存当日文；客户端发 `Accept-Language`，服务器按权重选择消息和演示商品内容。

`packages/i18n/src/messages.ts` 定义统一键集合及五套完整词典。新增键必须同次补齐所有语言，TypeScript 会检查。页面通常把 Zod 校验结果对应到翻译后的文案，而不是直接显示 Schema 中的中文字符串。服务器错误词典另在 `packages/server/src/http.ts`；不要把翻译文字当稳定的错误码。

内置商品有按语言呈现的文本。PostgreSQL 仓储只选择中、英、日三个标题列，店铺、配送、描述来自共享列；香港与台湾使用中文标题。真实商品系统需要所有编辑字段的翻译模型、缺失回退和内容审核。当前货币只是按不同语言格式显示人民币，并非汇率转换或多币种结算。

文档每个侧边栏主题都有英、中、日同路径页面，配置在 `docs/.vitepress/config.mts`。新增或改契约先写英文，再同步 `/zh/` 与 `/ja/`，保持命令、路径和“当前/提案”的语义一致。用 `pnpm build:docs` 验证三套页面。
